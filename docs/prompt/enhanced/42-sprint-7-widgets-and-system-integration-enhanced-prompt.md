## Mission Statement

Implement Sprint 7 as a bounded system-surface enhancement that adds local-first WidgetKit and ActivityKit support for readiness, expiring supplies, rotating preparedness tips, Emergency Mode quick access, and active protocol progress without widening OSA's privacy or architecture boundaries.

## Technical Context

OSA already contains most of the product data needed for this sprint. The Home experience computes a `SupplyReadinessSnapshot` from live inventory and supply-template data, Inventory already exposes `itemsExpiringSoon(within:)`, Quick Cards are local editorial records available through `QuickCardRepository`, Emergency Mode is a dedicated stress-state surface, and checklists already persist active runs with a completion fraction. The missing piece is not business data. The missing piece is a system-surface bridge that can safely expose a bounded subset of that data to WidgetKit and ActivityKit.

The key design constraint is privacy plus boundary discipline. `docs/sdlc/05-technical-architecture.md` explicitly prefers clean folder boundaries over indiscriminate target growth, and `docs/sdlc/10-security-privacy-and-safety.md` keeps sensitive local content off system surfaces unless it is intentionally exposed. That means the widget extension should not become a second copy of the app's persistence stack and should not freely browse SwiftData records, Ask history, or note bodies. The preferred implementation is therefore:

1. add a single WidgetKit extension target through `project.yml`
2. keep app-domain logic in the existing app target and repository seams
3. derive a minimal widget-safe snapshot in the app target from existing repositories and support helpers
4. write that bounded snapshot into an App Group store that the widget extension can read
5. drive Live Activities from explicit `ChecklistRun` progress updates rather than background polling or full-store reads

This design lets the app remain the source of truth while the extension stays presentation-focused. It also keeps the sprint proportional. The widget extension should host all widget families plus the Live Activity `ActivityConfiguration`, but it should not introduce network clients, search, new persistence entities, or broad app-surface refactors.

The six implementation items for this sprint are:

1. XcodeGen target and entitlement scaffolding for WidgetKit and ActivityKit.
2. A bounded shared snapshot pipeline for readiness, expiry, rotating tip, and emergency quick actions.
3. A Readiness Score widget.
4. A Next Expiring Item widget.
5. A Rotating Tip widget plus Lock Screen Emergency Mode quick access.
6. A Live Activity for active emergency protocol progress with app-side start, update, and end coordination.

Prefer existing navigation seams. `OpenQuickCardIntent` already exists for quick-card deep links, and `AppNavigationCoordinator` is the correct place to add any new emergency-mode route or widget-origin launch behavior. Prefer existing domain seams. `InventoryRepository`, `QuickCardRepository`, and `ChecklistRepository` should remain the only sources of product truth; widgets read only the bounded snapshots derived from them.

3. **Fallback Live Activity scope:** if protocol-specific metadata is not reliable enough on the first pass, limit the Live Activity to any active run with a safe title and deterministic progress payload, then tighten eligibility in a follow-up slice once template-style metadata is fully validated.
